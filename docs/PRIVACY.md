# Privacy and data flow

VO Studio runs on your computer. Speech synthesis and forced alignment run on
ElevenLabs, so generation requires an internet connection.

## What goes where

| Data | Browser | Local server / files | ElevenLabs |
| --- | --- | --- | --- |
| API key | Input field and request memory; excluded from preferences | Used in request memory; excluded from job metadata | Sent over HTTPS in the `xi-api-key` header |
| Draft script | Text field; excluded from preferences | Not saved until generation starts | Sent when generating speech or aligning audio |
| Submitted script | Remains in the editor | Saved as `transcript.txt` in the recording's take folder | Sent for speech synthesis and alignment |
| Generated audio | Played through the local server | Saved as a WAV in the recording's take folder | Generated by ElevenLabs, then uploaded for alignment |
| Alignment | Available as a download | Saved as the provider's JSON response | Computed by ElevenLabs |
| Project and voice settings | Saved in `localStorage` | Saved in job metadata | Voice, model and synthesis settings sent as needed |

The browser remembers project name, episode ID, voice name and ID, model, sample
rate and voice settings. These preferences belong to the local URL's origin; a
different port has separate storage. The app does not put the API key or script
in `localStorage`.

New take folders use `outputs/recordings/<project>/<episode>/<recording and voice>/Take 01/`.
Job IDs remain in metadata. Existing `outputs/<job-id>/` folders remain in place
so previously exported scripts and After Effects projects keep their audio links.

Multi-voice mode remembers three separate voice profiles. Batch mode has its own
voice settings. The browser remembers the latest generated session identifier
for each mode. **Prepare speech** parses text locally without
saving it or contacting ElevenLabs. Once generation starts, the conversation's
message text and job identifiers are stored in `outputs/conversations/` so the
message view can be restored. Unsubmitted edits remain in browser memory only.

The destination folder is explicitly selected before generation in every mode.
The app checks that it is writable and saves numbered WAV files directly there;
existing files are preserved by assigning a new take number. The selected path
is held in server memory and returned to the local browser for display. Jobs
also record the exported file path in private local job metadata for After Effects
exports and, in Single voice and Batch, for timing sidecars alongside the WAV. Paths
are not sent to ElevenLabs or returned in public job data. Select the destination
again after reloading. Local history retains its own audio copy and alignment JSON.

Uploaded CSV contents are read in the browser and parsed by the local server.
Preparation makes no external requests. Generating a CSV batch stores submitted
clip texts and identifiers in local session/job metadata and writes scripts, WAV
candidates, timing files and settings metadata to the chosen folder. Only the
speech text, voice and synthesis settings are sent for synthesis. The API key is
excluded from CSV exports, candidate metadata and preferences.

After Effects exports run locally without provider requests. Composition settings
(resolution, subtitles and frame rate) are remembered in browser preferences.
The `.jsx` script contains project/voice names, spoken words, timing and local WAV
paths, but no API key. It is saved in the chosen folder and cached under
`outputs/after_effects/` for downloading. Audio is referenced, not embedded or
uploaded. Running the script imports the referenced files into After Effects.

## Local safeguards

- The server binds to `127.0.0.1` and validates the request Host header and POST
  Origin header.
- API keys are excluded from the job data returned to the browser and written
  to metadata. Error handling redacts the submitted key and known local paths
  before returning or saving error messages.
- Request bodies are not logged by the app. The interface uses local assets,
  with no analytics scripts or remote font requests.
- `outputs/`, environment files, logs, Finder aliases and OS metadata are ignored
  by Git. The public preview contains no account or project data.

Output files are ordinary, unencrypted files on your computer. They contain your
script, voice details, project names and audio, and should be treated accordingly.
The server is designed for a single local user; it has no login system and should
not be exposed as a public service. Origin checks are not authentication against
other programs running on your computer.

## Remove local data

Stop the app and delete the relevant job directory under `outputs/` to remove its
audio, transcript, alignment and history. Clear the site's storage in your browser
to remove saved preferences. Close the tab to discard the in-memory key and draft
script. Browser extensions and password managers operate independently of the app.

For conversations, also remove their records under `outputs/conversations/` and
the exported WAV files in your selected destination if you want to remove those
copies. Removing local history alone does not remove destination files.
Remove `outputs/after_effects/` and exported JSX files to remove composition export
copies. Deleting referenced WAV files will also break those scripts' audio links.

Deleting local files does not delete data held by ElevenLabs. Provider retention
and processing are governed by your account and ElevenLabs policies; this app does
not request a special zero-retention mode.
